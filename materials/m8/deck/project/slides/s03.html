ก.ย. 2023: ลิงก์แชร์ลิงก์เดียว เปิดข้อมูล 38TB

  • ทีมวิจัย AI ของ Microsoft แชร์ไฟล์ training data บน GitHub
  • ลิงก์ที่ใช้ (Azure SAS token) เปิด ทั้ง storage account ไม่ใช่แค่ไฟล์เดียว
  • สิทธิ์ “แก้ไขได้” ไม่ใช่ “อ่านอย่างเดียว” · ลิงก์หมดอายุปี 2051
  • ข้างในมี backup เครื่องพนักงาน รหัสผ่าน และข้อความ Teams 30,000+ ข้อความ
  • Wiz พบและแจ้ง Microsoft ปิดภายใน 2 วัน

ปัญหาไม่ใช่ AI ฉลาดเกินไป แต่คือ คนแชร์กว้างเกินไป

ก่อนทบทวนกฎ ขอเล่าเรื่องจริงเรื่องหนึ่งครับ เดือนกันยายน 2023 ทีมวิจัย AI ของ Microsoft แชร์ไฟล์ training data ไว้บน GitHub ปัญหาคือลิงก์ที่ใช้แชร์ ซึ่งเป็น Azure SAS token ไม่ได้เปิดแค่ไฟล์เดียว แต่เปิดทั้ง storage account แถมสิทธิ์ยังเป็น "แก้ไขได้" ไม่ใช่ "อ่านอย่างเดียว" และลิงก์หมดอายุปี 2051 ครับ ข้างในมีอะไรบ้าง? มี backup เครื่องพนักงาน รหัสผ่าน และข้อความ Teams มากกว่า 30,000 ข้อความ รวมแล้ว 38TB ทีม Wiz เป็นคนพบและแจ้ง Microsoft ซึ่งปิดได้ภายใน 2 วัน ที่ผมเลือกเรื่องนี้มาปิดวัน เพราะไม่มีใครตั้งใจทำผิดเลยครับ เป็นทีมที่เก่งเรื่อง AI ด้วยซ้ำ แค่ตั้งค่าการแชร์ผิดจุดเดียว ปัญหาจึงไม่ใช่ AI ฉลาดเกินไป แต่คือคนแชร์กว้างเกินไป Claude Team เองก็แชร์ Project, Artifact และไฟล์ output ได้ง่ายมาก แชร์ง่าย ก็แชร์ผิดได้ง่ายครับ ลองนึกดูนะครับ มีลิงก์ไหนที่คุณเคยแชร์ แล้วไม่เคยกลับไปปิดเลยบ้างไหม? ---------- [1:30] เล่า 1.5 นาที · เคสจริงจาก Wiz Research (18 ก.ย. 2023) และ Microsoft MSRC ยืนยัน (SOURCES #1, #2) ไทม์ไลน์: ลิงก์อยู่บน GitHub ตั้งแต่ ก.ค. 2020 · Wiz แจ้ง 22 มิ.ย. 2023 · Microsoft ยกเลิก token 24 มิ.ย. 2023 · MSRC ระบุว่าไม่มีข้อมูลลูกค้าหลุด (พูดข้อนี้ถ้ามีคนถาม) ทำไมเลือกเคสนี้ปิดวัน: ไม่มีใคร "ตั้งใจ" ทำผิด แค่ตั้งค่าการแชร์ผิด 1 จุด เชื่อมกับ M1: "แชร์ง่าย = แชร์ผิดก็ง่าย" คำถามชวนคิด (ไม่ต้องให้ตอบออกเสียง): "ลิงก์ไหนที่คุณเคยแชร์ แล้วไม่เคยกลับไปปิดเลย?"
