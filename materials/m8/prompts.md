## M8-P01 · สรุปสถานะเพื่อเริ่มแชตใหม่

ใช้เมื่อแชตยาว Claude เริ่มลืมเงื่อนไขช่วงแรก หรือ Settings → Usage ใกล้เต็ม

```text
แชตนี้ยาวแล้ว ช่วยสรุปให้ฉันนำไปเริ่มแชตใหม่ ไม่เกิน 200 คำ ในหัวข้อต่อไปนี้:
1) เป้าหมายของงาน (1 บรรทัด)
2) เงื่อนไข/ข้อกำหนดที่ตกลงกันแล้ว (bullet)
3) สิ่งที่ทำเสร็จแล้ว และไฟล์/ผลลัพธ์ที่ได้
4) สิ่งที่ยังค้าง เรียงตามลำดับที่ควรทำ
5) คำถามที่ยังไม่ได้คำตอบ
ห้ามใส่ข้อมูลส่วนบุคคล ตัวเลขดิบ หรือเนื้อหาเอกสารยาว ๆ ในสรุป ให้อ้างชื่อไฟล์แทน
```
✅ ตรวจ: สรุปครบเงื่อนไขสำคัญไหม · ไม่มีข้อมูล 🟡🔴 · แล้วจึงเปิดแชตใหม่ (ใน Project เดิมถ้ามี) และวางสรุปนี้เป็นข้อความแรก

## M8-P02 · ขอแผนแบ่งงาน + เลือก model ก่อนลงมือ

```text
ฉันจะทำงานนี้: {อธิบายงาน เช่น สรุปรายงาน near-miss รายเดือนจาก 8 site ไฟล์ CSV รวม 120,000 แถว (ข้อมูลสมมติ)}
อย่าเพิ่งลงมือ ช่วยวางแผนให้ใช้ usage อย่างคุ้มค่า:
1) แบ่งงานเป็นขั้น (ไม่เกิน 5 ขั้น) บอกว่าขั้นไหนควรทดลองกับตัวอย่างเล็กก่อน
2) แต่ละขั้นแนะนำ model ที่พอดี (Haiku / Sonnet / Opus) พร้อมเหตุผล 1 บรรทัด
3) ส่วนไหนควรให้เขียนสคริปต์คำนวณแทนการอ่านข้อมูลทั้งหมด
4) สิ่งที่ควรเก็บไว้ใน Project instructions หรือทำเป็น Skill ถ้างานนี้ทำซ้ำทุกเดือน
5) จุดที่ฉันต้องตรวจ (Human-in-the-Loop) อย่างน้อย 2 จุด
ตอบเป็นตาราง: ขั้น · ทำอะไร · model · เหตุผล · จุดตรวจ
```
✅ ตรวจ: ไม่มีขั้นที่ใช้ Opus โดยไม่จำเป็น · มีขั้นทดลองตัวอย่างเล็ก · มีจุดตรวจของคน

## M8-P03 · Interview pattern หา use case สำหรับแผน 30 วัน

```text
ฉันเพิ่งอบรม Claude for Business จบ อยากได้แผนใช้งาน 30 วันที่ทำได้จริง
ช่วยสัมภาษณ์ฉันทีละคำถาม (ไม่เกิน 6 คำถาม รอคำตอบก่อนถามข้อต่อไป) เพื่อหา:
1) งานที่ทำซ้ำทุกสัปดาห์/เดือน และกินเวลาเยอะ (ขอตัวอย่างงาน ไม่ต้องใส่ข้อมูลจริง)
2) สีของข้อมูลในงานนั้นตาม Data Traffic Light (🟢 ใช้ได้ · 🟡 ต้อง anonymize · 🔴 ห้ามใส่ Claude)
3) เครื่องมือที่เหมาะ: Chat / Project / Skill / Cowork / Artifact และ Connector (SharePoint / Outlook เท่านั้น)
4) จุดที่ต้องมีคนตรวจ/อนุมัติ และใครเป็น buddy ที่จะช่วยเช็ก
ถ้างานที่ฉันเล่าเป็นข้อมูล 🔴 ให้บอกตรง ๆ และเสนองานอื่นแทน
เมื่อครบ ให้สรุปเป็นแผน 4 สัปดาห์ ตาราง: สัปดาห์ · สิ่งที่ทำ · ผลลัพธ์ที่วัดได้ · check-in
```
✅ ตรวจ: งานที่เลือกเป็น 🟢 (หรือ 🟡 ที่ anonymize ได้) · Connector มีแค่ SharePoint/Outlook · แต่ละสัปดาห์มีผลลัพธ์ที่วัดได้ แล้วค่อยกรอกลง `plan-30-days.html`

## M8-P04 · ร่าง check-in 4 ครั้ง (Drafts เท่านั้น)

```text
จากแผน 30 วันด้านบน ช่วยร่างข้อความนัด check-in 15 นาที 4 ครั้ง ทุกวันศุกร์ เริ่ม {วันที่}
ผู้รับ: {buddy@example.com} (ตัวอย่าง) · หัวข้อ: "Check-in แผน Claude 30 วัน · สัปดาห์ที่ N"
เนื้อหาแต่ละครั้ง 3 บรรทัด: เป้าหมายสัปดาห์นี้ · คำถามที่จะคุย · สิ่งที่ต้องเตรียม
ทำเป็นร่างเท่านั้น ห้ามส่งหรือสร้างนัดหมายเอง ถ้าเชื่อม Outlook อยู่ให้บันทึกไว้ใน Drafts แล้วรายงานว่าบันทึกไว้ที่ไหน
```
✅ ตรวจ: ยังอยู่ใน Drafts ไม่ถูกส่ง · ผู้รับถูกคน · เราเป็นคนกดส่ง/สร้างนัดเอง

## M8-P05 · กติกาประจำ Project: สิ่งที่ไม่ให้ Claude ทำ

วางใน **Project instructions** ครั้งเดียว ใช้ได้กับทุกแชตใน Project นั้น (ไม่ต้องพิมพ์ซ้ำ = ประหยัด usage)

```text
กติกาการทำงานใน Project นี้ (ใช้ทุกแชต):
- ข้อมูลที่ฉันให้เป็น 🟢 หรือ anonymize แล้ว ถ้าพบชื่อคน เบอร์ เลขบัตร เงินเดือน ข้อมูลสุขภาพ รหัสผ่าน หรือราคา/สัญญาที่ยังเจรจา ให้หยุดและเตือนฉันก่อนทำต่อ
- ก่อนลงมือทุกงานที่มีหลายขั้น ให้เสนอแผนสั้น ๆ และรอฉันอนุมัติ (Plan → Approve → Execute)
- ห้ามส่งอีเมล แชร์ หรือโพสต์เอง ให้ร่างไว้ใน Drafts หรือไฟล์ใน output/ เท่านั้น
- ห้ามลบหรือเขียนทับไฟล์ต้นฉบับ ให้ทำงานบนสำเนา (copy-before-write)
- ห้ามตัดสินใจแทนฉันเรื่องอนุมัติ เงิน สัญญา หรือบุคคล ให้สรุปทางเลือกพร้อมข้อดีข้อเสีย
- ใช้เฉพาะ SharePoint และ Outlook เป็น Connector ห้ามเสนอ Google Drive หรือบริการอื่น
- ห้ามติดตั้ง Skill หรือรัน script ที่ไม่ได้มาจาก Project นี้
- ทุกตัวเลขให้ระบุที่มา (ไฟล์ · ชีต · แถว) และบอกเมื่อไม่แน่ใจ
- ตอบภาษาไทย กระชับ ถ้างานไหน model ที่เล็กกว่า (เช่น Haiku) ทำได้ดีพอ ให้แนะนำฉันเปลี่ยน model
```
✅ ตรวจ: ลองถามในแชตใหม่ "ส่งอีเมลสรุปให้หัวหน้าเลย" Claude ควรเสนอร่างแทนการส่ง

## M8-P06 · เช็กแผนก่อนกด Approve (4 คำถาม)

ใช้ต่อจากแผนที่ Cowork เสนอ ก่อนกดอนุมัติ

```text
ก่อนฉันอนุมัติแผนนี้ ช่วยตรวจแผนของคุณเองด้วย 4 คำถาม ตอบเป็นตาราง (ขั้น · คำถาม · ใช่/ไม่ · ปรับอย่างไร):
1) ส่ง: มีขั้นไหนส่งอีเมล แชร์ หรือโพสต์ออกนอกตัวฉันไหม → ถ้ามี เปลี่ยนเป็นร่างใน Drafts
2) ลบ: มีขั้นไหนลบ ย้าย หรือเขียนทับไฟล์ต้นฉบับ/ไฟล์ที่แชร์ไหม → ถ้ามี เปลี่ยนเป็นทำบนสำเนา
3) ตัดสิน: มีขั้นไหนตัดสินใจแทนคน (อนุมัติ เงิน สัญญา บุคคล) ไหม → ถ้ามี เปลี่ยนเป็นสรุปทางเลือก
4) แดง: มีขั้นไหนต้องอ่านข้อมูล 🔴 หรือระบบนอก SharePoint/Outlook ไหม → ถ้ามี ตัดขั้นนั้นออก
แล้วเสนอแผนฉบับปรับปรุง โดยยังไม่ลงมือจนกว่าฉันจะพิมพ์ "อนุมัติ"
```
✅ ตรวจ: ทุกข้อที่ตอบ "ใช่" ถูกปรับแล้ว · ไม่มีขั้นใดทำงานกับไฟล์ต้นฉบับโดยตรง

## M8-P07 · ทบทวนผลสัปดาห์ (check-in ศุกร์)

```text
นี่คือบันทึกสัปดาห์ที่ {N} ของแผน Claude 30 วันของฉัน (ไม่มีข้อมูลจริงของบริษัท):
- งานที่ทำ: {งาน · กี่ครั้ง}
- เวลาที่ใช้ก่อน/หลังใช้ Claude: {นาที/ครั้ง}
- สิ่งที่ติดขัด: {...}
- ข้อผิดพลาดที่ตรวจเจอ: {...}
ช่วยสรุป 3 ส่วน: (1) ได้ผลแค่ไหน (เวลาประหยัดรวม) (2) ความเสี่ยงที่ควรระวังสัปดาห์หน้า (ข้อมูล · การแชร์ · HITL) (3) ขั้นต่อไป 1–2 ข้อที่เล็กพอทำได้ใน 1 สัปดาห์
ถ้างานนี้ทำซ้ำได้ ให้แนะนำว่าควรทำเป็น Project instructions หรือ Skill หรือไม่
```
✅ ตรวจ: ตัวเลขเวลาเป็นของเราเอง ไม่ใช่ Claude เดา · ขั้นต่อไปเล็กพอทำจริง
