ต่อไปคือเรื่องที่สำคัญที่สุดของโมดูลนี้ครับ Read กับ Write ความเสี่ยงไม่เท่ากัน Read คือค้น อ่าน สรุป ข้อมูลต้นทางไม่เปลี่ยน ถ้าพลาด เลวร้ายสุดคือเราได้สรุปผิด ซึ่งเราตรวจแล้วแก้ได้ก่อนนำไปใช้ แต่ Write คือแก้ไฟล์ ส่งเมล นัดประชุม สร้างหรือลบ อันนี้ไฟล์หรืออีเมลจริงเปลี่ยนทันทีครับ ถ้าพลาด คือทับงานคนอื่น หรือส่งผิดคน และเท่าที่ Help Center เขียนไว้ ยังไม่ได้ระบุว่ามีขั้นยืนยันก่อนแก้ไฟล์หรือส่งอีเมล เราจึงต้องสร้างจุดอนุมัติเอง คือ Plan → Approve → Execute ดูในแผนภาพครับ ถ้าไม่อนุมัติ ก็วนกลับไปทำแผนใหม่ อีกทางหนึ่งที่เขียนได้โดยไม่รู้ตัว คือให้ Cowork แก้ไฟล์ในโฟลเดอร์ที่ sync กับ SharePoint หรือ OneDrive เซฟปุ๊บ ขึ้น SharePoint ปั๊บ กฎของหลักสูตรเราคือ งาน write ทุกงานต้องมีคนอนุมัติ และทำกับสำเนาก่อนเสมอครับ ---------- [4:00] Read: เลวร้ายสุดคือได้สรุปผิด ซึ่งเราตรวจได้ก่อนใช้ Write: เปลี่ยนของจริงทันที · Help Center ไม่ได้ระบุขั้นยืนยันก่อนแก้ไฟล์หรือส่งอีเมล (มีแค่ Teams ที่ถามก่อนส่ง) → สร้างจุดอนุมัติเอง: Plan → Approve → Execute อีกเส้นทางที่ “เขียน”: Cowork แก้ไฟล์ในโฟลเดอร์ที่ sync กับ SharePoint/OneDrive (เซฟปุ๊บ ขึ้น SharePoint ปั๊บ) กฎของหลักสูตร: งาน write ทุกงานต้องมีคนอนุมัติ และทำกับ “สำเนา” ก่อน
