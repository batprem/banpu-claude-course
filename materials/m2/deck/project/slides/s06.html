เมื่อ AI agent ลงมือโดยไม่มีจุดหยุด

  • ก.ค. 2025: Jason Lemkin (SaaStr) ใช้ AI coding agent ของ Replit สร้างแอป
  • สั่งชัดว่า “code freeze ห้ามแก้” — agent ยังรันคำสั่งลบ production database
  • ข้อมูลผู้บริหารกว่า 1,200 รายการหาย และ agent รายงานผิดว่ากู้คืนไม่ได้
  • CEO Replit ขอโทษ และเพิ่มการแยก dev/prod + โหมด planning-only

บทเรียน: คำสั่งในแชตไม่พอ ต้องมีสำเนา + จุดอนุมัติก่อน Execute

แหล่งที่มา: Fortune, 23 Jul 2025 · ดู SOURCES.md

ขอเล่าเรื่องจริงเรื่องหนึ่งครับ เรื่องนี้ไม่ใช่ Claude นะครับ แต่เป็นบทเรียนของ AI agent ที่ลงมือได้ทุกตัว กรกฎาคม 2025 คุณ Jason Lemkin จาก SaaStr ใช้ AI coding agent ของ Replit สร้างแอป เขาสั่งชัดเจนว่า code freeze ห้ามแก้ แต่ agent ก็ยังรันคำสั่งลบ production database ไป ข้อมูลผู้บริหารกว่า 1,200 รายการหายไป แล้ว agent ยังรายงานผิดอีกว่ากู้คืนไม่ได้ สุดท้าย CEO ของ Replit ออกมาขอโทษ และเพิ่มการแยก dev กับ prod รวมถึงโหมด planning-only ถามห้องหน่อยครับ เรื่องนี้พลาดตรงไหน หนึ่ง เขาสั่งห้ามแล้ว แต่ไม่มีกลไกบังคับ สอง ใช้ database เดียวกันทั้ง dev และ prod ก็คือไม่มี copy-before-write สาม วิธีแก้ของ Replit คือโหมดวางแผนก่อน ซึ่งก็คือ Plan → Approve → Execute นั่นเอง บทเรียนคือ คำสั่งในแชตอย่างเดียวไม่พอครับ ต้องมีสำเนา และจุดอนุมัติก่อน Execute ข่าวดีคือใน Cowork เราทำได้ง่ายกว่า แค่ให้เข้าถึงเฉพาะโฟลเดอร์สำเนา และสั่งว่า เสนอแผนก่อน ---------- [6:00–7:30] ประมาณ 1 นาทีครึ่ง Cue: เล่าเป็นเรื่อง ไม่ต้องอ่านสไลด์ · ถามห้อง "พลาดตรงไหน" แล้วค่อยเฉลย 3 ประเด็น ย้ำ: ไม่ใช่ Claude แต่เป็นบทเรียนของ "agent ที่ลงมือได้" ทุกตัว ประเด็น: (1) สั่งห้ามแล้วแต่ไม่มีกลไกบังคับ (2) database เดียวกันทั้ง dev/prod = ไม่มี copy-before-write (3) Replit เพิ่ม planning-only mode = Plan → Approve → Execute เชื่อมกลับ Cowork: เข้าถึงเฉพาะโฟลเดอร์สำเนา + สั่ง "เสนอแผนก่อน" ระวังตัวเลข: รายงานข่าวต่างกันเล็กน้อย (≈1,200 ผู้บริหาร / ≈1,100–1,200 บริษัท) ใช้คำว่า "กว่า 1,200" พอ แหล่งที่มา: Fortune, 23 Jul 2025 · ดู SOURCES.md
