## M6-P01 · Demo: ร่าง Weekly Insight ครั้งแรก

```text
ก่อนเริ่ม ให้ทวนเป้าหมายด้วยคำของคุณเอง 3 บรรทัด แล้วรอฉันยืนยัน

เป้าหมาย: ร่าง "Weekly Energy & Ops Insight" สัปดาห์ล่าสุด 1 หน้า ภาษาไทย
แหล่งข้อมูล (อ่านอย่างเดียว):
1) Web: ข่าวสาธารณะ 7 วันล่าสุด เรื่อง ราคาถ่านหินเอเชีย, LNG เอเชีย, นโยบายพลังงานหมุนเวียนไทย, ราคา inverter/BESS
2) Outlook: อีเมลที่หัวเรื่องขึ้นต้น [PRJ- หรือมีคำว่า "ขออนุมัติ" ใน 7 วันล่าสุด
3) Meeting notes: ไฟล์ในโฟลเดอร์ meeting_notes ที่แก้ไขใน 7 วันล่าสุด
ห้ามใส่ชื่อโครงการ ชื่อคน หรือตัวเลขภายในลงในคำค้นเว็บ

รูปแบบ 5 หัวข้อ:
1. สรุป 3 บรรทัด
2. ความเสี่ยงสูงสุด 3 เรื่อง (ตาราง: เรื่อง · ที่มา · ข้อเสนอให้คนตัดสินใจ)
3. ข่าวภายนอก ≤ 5 ข่าว (ข่าว · ผลต่อเรา · ลิงก์)
4. Action items ที่ครบกำหนดใน 7 วัน (งาน · ผู้รับผิดชอบ · กำหนด · ที่มา)
5. สิ่งที่ไม่แน่ใจ / ข้อมูลขัดกัน

กฎ: ทุกข้อต้องมีที่มา (ลิงก์ / หัวเรื่องอีเมล+วันที่ / ชื่อไฟล์) · ถ้าข้อมูลขัดกันให้แสดงทั้งสองค่า ห้ามเลือกเอง
ห้ามส่งอีเมล ห้ามแก้ไฟล์ต้นทาง · บรรทัดแรกเขียน "สถานะ: ร่าง · รอคนตรวจ" บรรทัดสุดท้ายเขียน "🛑 หยุดรอคนตรวจ" แล้วหยุด
```

## M6-P02 · Demo: แปลงเป็น Scheduled task

```text
/schedule
ตั้งงานนี้เป็น Scheduled task ชื่อ "Weekly Energy & Ops Insight"
รอบ: ทุกสัปดาห์ วันจันทร์ 08:00
ใช้ขั้นตอนและรูปแบบเดียวกับที่เราเพิ่งทำ (M6-P01) โดยไม่ต้องทวนเป้าหมายและไม่ต้องรอฉันยืนยันกลางทาง
Output: บันทึกเป็นไฟล์ output/weekly_insight_[YYYY-MM-DD].md (ห้ามเขียนทับไฟล์เดิม)
Approval: ให้ถามฉันก่อนทุก action ที่เขียน แก้ ส่ง หรือลบ
เจ้าของงาน: [ชื่อของคุณ] · ใส่ชื่อนี้ที่หัวรายงาน
ก่อนกด Schedule ให้แสดงสรุป: ชื่อ · รอบ · แหล่ง · output · approval · งานนี้ต้องเปิดเครื่องไว้ไหม
```

## M6-P03 · Workshop (ก): รายงานสถานะโครงการรายสัปดาห์

ใส่ในช่อง Prompt ของ **Scheduled → New task → Set up manually** · รอบ: Weekly (จันทร์ 08:00) · โฟลเดอร์: `Documents/Claude-Workshop/M6`

```text
งาน: ร่าง "รายงานสถานะโครงการรายสัปดาห์" 1 หน้า ภาษาไทย ให้ [ชื่อเจ้าของงาน] ตรวจก่อน 09:30

Input (อ่านอย่างเดียว ห้ามแก้):
- เส้นทาง A: Outlook อีเมลหัวเรื่อง [PRJ- และ "ขออนุมัติ" 7 วันล่าสุด · SharePoint site "M3-Training" ไฟล์ Project_Tracker และ Issue_Log
- เส้นทาง B: โฟลเดอร์ input/ (m3_outlook/*.eml, m3_sharepoint/*.csv, meeting_notes/*.md, รายงาน M4 ล่าสุดถ้ามี)

Process:
1. ตารางโครงการที่สถานะ At risk / Delayed หรือมีสัญญาณเสี่ยงในอีเมล/ประชุม
2. ความเสี่ยงสูงสุด 3 เรื่อง + คำขออนุมัติที่ยังค้าง (จำนวนเงิน · กำหนดตอบ)
3. จุดที่แหล่งข้อมูลขัดกัน แสดงทั้งสองค่า ห้ามเลือกเอง

Output:
- ไฟล์ output/weekly_status_[YYYY-MM-DD].docx (ห้ามเขียนทับไฟล์เดิม)
- เส้นทาง A เท่านั้น: สร้าง "ร่าง" อีเมลใน Outlook Drafts ถึง [อีเมลผู้รับ @example.com] ห้ามกดส่ง

Checkpoint: บรรทัดแรก "สถานะ: ร่าง · รอ [ชื่อเจ้าของงาน] ตรวจ" · ทุกข้อมีที่มา · ถ้าแหล่งไหนเข้าไม่ได้ให้บอกที่หัวรายงาน
จบด้วย "🛑 หยุดรอคนตรวจ" และสรุปว่าได้เขียนไฟล์อะไรไปบ้าง
```

```text
งาน: ร่าง "Weekly Energy & Ops Insight" 1 หน้า ภาษาไทย ให้ [ชื่อเจ้าของงาน] ตรวจ
Input (อ่านอย่างเดียว):

Checkpoint: ทุกข้อมีที่มา · ห้ามส่งอีเมล ห้ามแก้ไฟล์ใน input/ · บรรทัดแรก "สถานะ: ร่าง · รอคนตรวจ" · จบด้วย "🛑 หยุดรอคนตรวจ"
```

## M6-P05 · Workshop (ค): ให้ Claude สัมภาษณ์เพื่อออกแบบ task

ใช้กับ **Scheduled → New task → Create with Claude** หรือแชต Cowork ปกติ

```text
ฉันอยากตั้งงานอัตโนมัติ 1 งาน: [อธิบายงานซ้ำของคุณ 1–2 ประโยค]
สัมภาษณ์ฉันทีละคำถาม (ไม่เกิน 6 คำถาม) ให้ครบ 6 ช่อง: เมื่อไร · Input · Process · Output · Checkpoint · Owner
กฎที่ต้องอยู่ใน task เสมอ: อ่านอย่างเดียวจากต้นทาง · เขียนเฉพาะ output/ หรือ Drafts · ห้ามส่งออกเอง · ถามก่อนทุก action ที่เขียน/ส่ง/ลบ
ถ้าฉันตอบว่าจะใช้ข้อมูล 🔴 (ข้อมูลลับ ข้อมูลส่วนบุคคล ตัวเลขการเงินที่ยังไม่เปิดเผย) ให้เตือนและเสนอทางที่ปลอดภัยกว่า
สุดท้ายสรุปเป็นตาราง 6 ช่อง + prompt ของ task ให้ฉันยืนยันก่อนกด Schedule
```

## M6-P06 · ตรวจร่างรอบทดสอบ (self-check)

วางในแชตเดียวกับผลของ **Run now** หรือแชตใหม่ที่เปิดไฟล์ร่าง

```text
ตรวจร่างที่เพิ่งสร้างด้วย checklist นี้ ตอบเป็นตาราง ✅/❌ + หลักฐาน:
1. บรรทัดแรกบอกว่าเป็นร่างและชื่อเจ้าของงาน
2. ทุกข้อมีที่มาที่เปิดตรวจได้
3. ตัวเลขสำคัญ 3 ตัว: ระบุค่าในร่าง และค่าที่ต้นทาง ตรงกันไหม
4. มีหัวข้อ "ไม่แน่ใจ/ขัดกัน" และไม่ได้เลือกค่าเอง
5. ไม่มีอีเมลถูกส่ง ไม่มีไฟล์ต้นทางถูกแก้ (บอกรายการไฟล์ที่เขียนทั้งหมด)
6. ไม่มีข้อมูล 🔴 (ข้อมูลส่วนบุคคล ข้อมูลลับ)
ห้ามแก้ร่างเอง ถ้ามี ❌ ให้เสนอวิธีแก้ prompt ของ task แทน
```
