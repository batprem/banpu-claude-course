1. ความเป็นมาและวัตถุประสงค์

บ้านปูได้เปิดใช้ Claude ผ่าน Team License สำหรับพนักงานกว่า 200 คน ภายใต้การขับเคลื่อนของทีม Hi-I (AI Transformation Working Group) โดยมีเป้าหมายให้พนักงานทุกคนใช้ AI ได้อย่างมีประสิทธิภาพและปลอดภัยภายในสิ้นปีนี้ จากการประชุมเมื่อวันที่ 15 ต.ค. 2569 ทีม Hi-I ได้ให้ข้อกำหนด (requirements) 16 ข้อ ซึ่งเน้นการใช้งานจริงในบริบท Microsoft 365 ของบ้านปู ความปลอดภัยของข้อมูล และการสร้างงานอัตโนมัติที่มีคนตรวจสอบในจุดสำคัญ

เอกสารฉบับนี้ปรับปรุงจากโครงร่างเดิม 6 โมดูล ให้เป็น 8 โมดูลใน 1 วัน โดยแยก Automation ออกเป็นโมดูลเฉพาะตามความต้องการเพิ่มเติมของลูกค้า และครอบคลุม requirement ครบทั้ง 16 ข้อ (ดูตารางในหัวข้อที่ 5)

วัตถุประสงค์ของหลักสูตร

  • ให้พนักงานเข้าใจว่า Claude / Cowork ทำงานแบบ “Agent” อย่างไร และเลือกใช้ Chat, Project, Skill, Agent และ Artifacts ได้เหมาะกับงาน
  • สร้างวินัยด้าน Security & Sensitive Data เป็นพื้นฐานบังคับ: ข้อมูลอ่อนไหวต้องไปที่เครื่องมือที่บริษัทกำหนดสำหรับข้อมูลอ่อนไหวเท่านั้น ไม่ใช่ Claude
  • ฝึกใช้ Claude กับไฟล์และ Connector ของ Microsoft 365 ที่ IT อนุมัติ (SharePoint, Outlook) อย่างปลอดภัย รวมถึงหลัก copy-before-write
  • สร้างงานเอกสารจริงแบบ Document Factory จากหลายแหล่งข้อมูลหลายรูปแบบ และต่อยอดเป็นงานอัตโนมัติที่มี Human-in-the-Loop
  • รู้ข้อจำกัดจริงของเครื่องมือ (ขนาดไฟล์ usage limit ของ Team plan) และวิธีแก้ เพื่อให้นำกลับไปใช้กับงานจริงได้ทันที

2. กลุ่มเป้าหมายและสิ่งที่ต้องเตรียม

กลุ่มเป้าหมาย
  • พนักงานบ้านปูทุกระดับที่ได้รับ Claude Team License (ประมาณ 200+ คน)
  • ไม่ต้องมีพื้นฐานการเขียนโปรแกรม
  • แนะนำรุ่นละไม่เกิน 30–40 คน เพื่อให้ workshop ดูแลได้ทั่วถึง
  • ขอบเขต: Claude เท่านั้น (Copilot มีหลักสูตรแยก 2 วันโดยวิทยากรท่านอื่น)
สิ่งที่ผู้เรียนต้องเตรียม (Prerequisites)
  • Laptop ที่ติดตั้ง Claude Desktop (เวอร์ชันล่าสุด เปิดใช้ Cowork ได้)

3. ผลลัพธ์การเรียนรู้ (Learning Outcomes)

เมื่อจบหลักสูตร ผู้เรียนจะสามารถ:

#ผู้เรียนทำได้
1แยกแยะประเภทข้อมูล (ใช้ได้ / ต้องระวัง / ห้ามใส่ Claude) และอธิบายความต่างของ Personal, Team และ Enterprise ได้
2เลือกใช้ Chat, Project, Skill, Agent (Cowork) และ Artifacts ได้เหมาะกับลักษณะงาน
3ใช้ Cowork จัดการไฟล์และโฟลเดอร์แบบ Plan → Approve → Execute โดยมีจุดหยุดให้คนตรวจสอบ
4เชื่อม SharePoint และ Outlook ตามแนวคิด AI → Connect → Data → Execute พร้อมเข้าใจความเสี่ยงของการเขียนกลับ (write-back)
5รวมข้อมูลจาก PDF, CSV, Excel, Email และ SharePoint List (ภายใน + ภายนอก) เป็นรายงานเดียวในรูปแบบ Word / Excel / PDF / PPT หรือ Artifact
6สร้างและแชร์ Skill ภายในทีม พร้อมตรวจความปลอดภัยของ Skill จากภายนอกก่อนใช้
7ออกแบบงานอัตโนมัติ (scheduled task) เช่น รายงานประจำสัปดาห์และ Daily/Weekly Insight ที่มีจุด Human-in-the-Loop
8ใช้งานอย่างคุ้มค่าภายใต้ usage limit รายสัปดาห์ของ Team plan และรู้วิธีแก้เมื่อเจอข้อจำกัดจริง
9วิเคราะห์ use case จริงของตนเอง (data, connector, output, trade-off) และมีแผนใช้งาน 30 วันหลังอบรม

6. แผน Workshop และชุดข้อมูลตัวอย่าง (Sample Data Pack)

ทุก workshop ใช้ข้อมูลจำลอง (dummy data) ที่ออกแบบให้ใกล้เคียงบริบทธุรกิจพลังงานของบ้านปู ไม่มีข้อมูลจริงหรือข้อมูลอ่อนไหวของบริษัท และใช้ปริมาณข้อมูลขนาดจริงในบทเรียนข้อจำกัด เพื่อไม่ให้ผู้เรียนเห็นแต่กรณีสาธิตที่ “สวยเกินจริง”

ชุดข้อมูลรายละเอียด (จำลอง)ใช้ในโมดูล
Excel / CSV ปฏิบัติการข้อมูลผลผลิตและต้นทุนรายเดือนของเหมือง/โรงไฟฟ้าสมมติ 5–8 site ย้อนหลัง 3 ปี; Budget vs ActualM1, M2, M4
PDFรายงานตลาดพลังงานสาธารณะ, สัญญา supplier สมมติ, รายงานประจำปีตัวอย่าง (รวมไฟล์หลายร้อยหน้า)M2, M4
Email (Outlook)ชุดอีเมลจำลองในกล่องจดหมายทดสอบ: อัปเดตโครงการ, คำขออนุมัติ, สรุปการประชุมM3, M6
SharePoint List / SiteProject Tracker, Issue Log และ Excel ที่ “หลายคนแก้พร้อมกัน” สำหรับสาธิต copy-before-writeM3, M4
Meeting notesบันทึก/สรุปการประชุมจำลองสำหรับ Weekly InsightM6
ข้อมูลภายนอกข่าวและราคาพลังงานจากเว็บสาธารณะM4, M6
ชุดข้อมูลขนาดจริงCSV ~200,000 แถว, PDF 300+ หน้า, โฟลเดอร์ ~1,500 ไฟล์ ปี 2562–2569 ที่ตั้งชื่อไม่เป็นระบบ, รายงานที่ใหญ่เกินแนบอีเมลM2, M4 (ข้อจำกัด)
Data Traffic Light cardsตัวอย่างข้อมูล 15 รายการสำหรับฝึกจัดประเภทความอ่อนไหวM1, M8

ใช้ SharePoint site และ mailbox สำหรับทดสอบ (ถ้า IT จัดให้ได้) เพื่อไม่ให้ workshop เขียนข้อมูลลงพื้นที่ทำงานจริง หากไม่มี จะใช้โฟลเดอร์ส่วนตัวของผู้เรียนพร้อมไฟล์จาก Sample Pack แทน

7. แนวทาง Governance และ Security

หลักการสูงสุด: ข้อมูลอ่อนไหว (เช่น ข้อมูลส่วนบุคคล, ข้อมูลลับทางการค้า, ข้อมูลการเงินที่ยังไม่เปิดเผย) ไม่ใส่ใน Claude ให้ใช้เครื่องมือที่บริษัทกำหนดสำหรับข้อมูลอ่อนไหวตามนโยบาย IT ของบ้านปู และห้ามใช้บัญชี AI ส่วนตัว (Personal) กับข้อมูลบริษัท
ประเด็นแนวทางในหลักสูตร
ข้อจำกัดของ Team Licenseอธิบายความต่าง Personal / Team / Enterprise อย่างตรงไปตรงมา โดยเฉพาะการควบคุมของผู้ดูแล การเก็บ log และการ audit ที่ Team มีน้อยกว่า Enterprise ทำให้ ความรับผิดชอบส่วนหนึ่งอยู่ที่วินัยของผู้ใช้
Approved connectors เท่านั้นสอนและสาธิตเฉพาะ connector ที่ IT ยืนยัน (SharePoint, Outlook) ไม่สอน Google Drive หรือ connector ที่ไม่ได้รับอนุญาต
Copy-before-writeก่อนให้ Claude แก้ไฟล์ ให้ทำสำเนาก่อนเสมอ โดยเฉพาะไฟล์บน SharePoint ที่หลายคนแก้พร้อมกัน ตรวจผลแล้วจึงแทนที่
Human-in-the-Loopทุก flow ที่มีการลบ ย้าย เขียนทับ หรือส่งออกภายนอก ต้องมีจุดให้คนอนุมัติ (Plan → Approve → Execute)
Third-party Skill policyแนะนำให้ใช้ Skill ที่สร้างหรือรับรองภายในก่อน Skill จากภายนอกต้องตรวจที่มา สิทธิ์ script และการส่งข้อมูลออก ตาม checklist และควรมีผู้อนุมัติ (เช่น ทีม Hi-I / IT)
Automationงานอัตโนมัติให้ “ร่างและรอตรวจ” ก่อนส่ง ไม่ส่งอีเมลหรือเผยแพร่เองโดยไม่มีคนอนุมัติ และกำหนดเจ้าของงานที่ชัดเจน
Usage efficiencyเลือก model ให้เหมาะกับงาน แบ่งงานใหญ่ ใช้ Project/Skill เพื่อลดการส่ง context ซ้ำ ไม่ให้ทีมชน weekly limit
ข้อเสนอแนะ (Awareness): Microsoft Agent 365
Microsoft Agent 365 รองรับการเชื่อมต่อกับ Anthropic Claude ในฐานะ “connected platform” ทำให้ผู้ดูแลเห็นรายการ agent และ activity ของ agent ได้จาก Microsoft 365 admin center เพื่อช่วยด้าน governance/audit ปัจจุบันการเชื่อมต่อนี้ยังเป็น preview และรองรับ Claude Managed Agents ที่อยู่ใน Claude workspace (ใช้ workspace ID และ API key) ไม่ใช่การใช้งาน Claude Desktop แบบ Team โดยตรง เราจึงแนะนำให้ทีม IT/Hi-I ประเมินเรื่องนี้เป็นส่วนหนึ่งของแผน governance ระยะต่อไป
อ้างอิง: learn.microsoft.com/en-us/microsoft-agent-365/admin/connected-platforms-anthropic-claude
